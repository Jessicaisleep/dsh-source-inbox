# Source inbox

A single workbench that archives materials from **your own accounts** into a local knowledge base, so you no longer have to copy-paste them into the model by hand.

## Current status — Phase 1 (foundation + dropzone watcher) + Phase 2 (step-by-step guidance + self-reading + credential paste boxes) + Phase 3 (third-party capabilities moved in-tree)

Phase 0 (the foundation) is delivered and accepted; this release wires the first automatic source on top of it:

- **Unified workbench** in the sidebar: overview, import wizard, source-ladder status, and a browsable record list with a bounded Markdown / text-shadow preview.
- **Dual-track archiving** (§4.2 of the plan): text documents are *materialized* to disk; large media is kept as a *reference* (pointer only) plus a small text shadow, so it is still discoverable by search.
- **Unified schema** for every record (source, tier, title, timestamps, MIME, storage track, paths, tags, checksum, AI-conversation fields).
- **Import wizard**: accepts an absolute path to any official export / share / clipping bundle. Files are sniffed by magic bytes (wrong extensions are corrected), MIME-classified, de-duplicated by checksum, ZIP-expanded, and normalized.
- **Agent tools**: `inbox_status`, `inbox_sources`, `inbox_list`, `inbox_read`, `inbox_import`, `inbox_adapters`, `inbox_watch`, `inbox_scan`, `inbox_browser`, `inbox_open_login`, `inbox_read_page`, `inbox_credentials` (read-only, masked), `inbox_remove`, `inbox_fetch_url`, `inbox_export_weread`, `inbox_export_cubox`, `inbox_export_mail`.
- **Source registry + guidance**: 27 planned sources grouped A–G, mapped to a four-tier access ladder (L0 official API → L1 limited API → L2 logged-in web → L3 export/share), with official export/share instructions for each.
- **★ One-click official entry point per source** (new, 2026-11): 20 of 27 rows carry a button that opens that platform's **official** page in the system browser. Where an official API exists (Feishu app console, Tencent Docs MCP token, Notion integration, Baidu Netdisk open platform, Quark / Zhihu / Xiaohongshu) it goes to the login or console page; where access is logged-in-web only (公众号, Douyin / Xiaohongshu creator centres, 视频号助手) it goes to the login page; where the official channel is an export (语雀, 微信读书, flomo, DeepSeek / 元宝 / 豆包) it goes to the export entry. The other 7 rows are local channels (Obsidian vault, bookmarks, calendar) or official backups that must be produced inside the phone / desktop client (personal WeChat / QQ) — those rows state the reason instead of showing a dead button. Buttons only navigate: no embedded page, no credentials; the URL whitelist is https-only and goes through the host's `window.open → shell.openExternal`.
- **★ Phase 1 automatic adapter**: the *dropzone watcher* monitors a local drop directory; new files flow through the import wizard / dual-track archive / compliance gate (magic-byte correction, checksum de-dup, chat-database refusal). It is the shared base for all *file-producing* sources (per-platform official export ZIPs / WeChat "合并转发" ZIP / DeepSeek export / Yuanbao-to-doc). Configure the watch dir, poll interval, source id and tags from the workbench, and trigger "Scan now".
- **★ Step-by-step guidance after the login page** (Phase 2): a lone button drops you at the door and abandons you. All **27/27** rows now carry `steps` (84 in total) saying *what to click → what you get → where it goes*. Feishu is the full five steps (create a custom app in the developer console → grant docx/drive/wiki/bitable read scopes and publish them → copy App ID/Secret into the input box below → version & release **and get it approved** (the step everyone misses) → mint a user_access_token); Tencent Docs has four (including `400006` = bad/expired token, `400007` = not a super member, and the header must be `Authorization: <token>`, not Bearer); email has four (explicitly: the app password is **not** your login password).
- **★ The plugin reads it for you** (Phase 2): **7 sources / 11 pages** can be read directly — Quark drive, Cubox, Xiaoyuzhou/Ximalaya, Figma, the Douyin / Xiaohongshu / 视频号 / 即梦 creator backends, Zhihu collections, 公众号. Click "⟳ Read it for me": the plugin opens the page in **its own** Chromium; if the session is stale it surfaces that login page in the plugin window for you to scan, and the next click archives the list as a Markdown record (source, URL, read time, "not human-proofread").
  - **Why a separate browser**: your daily Chrome/Edge is never started with a debugging port, so it cannot be attached to — and attaching would expose the cookies of every site you use. A plugin-owned profile bounds what this can ever see.
  - **Whitelist gate**: only https pages declared in the source registry are readable; an empty whitelist allows nothing; suffix forgeries (`quark.cn.evil.com`), credentials inside the URL, and off-domain redirects are refused.
  - **A login wall is not success**: a stale session still returns HTTP 200 with a few hundred characters of 扫码登录 chrome. That is detected as `loginRequired`, **not archived**, and the page is opened for you — instead of quietly storing the login page as knowledge. The test is the login box's own UI strings (`扫码登录` / `请先登录` / `Log in to continue` …) plus `/login`, `/signin`, `passport.` in the URL — **not page length**: a logged-out Douyin page is 1127 characters, so a length guard stores the login page as content.
- **★ Credentials are no longer "go write the file yourself"** (Phase 2.3): the guidance used to end with "you get App ID / App Secret → put them in `_secrets\feishu.json`", which silently meant *create the file, guess the JSON keys, and hand-write the format* — a typo produced no error, the adapter just read nothing. Now **8 sources that need a credential (Feishu / Tencent Docs / Notion / Baidu Netdisk / WeRead / Cubox / Figma / email, 14 fields in total) render real input boxes on their row**; secret fields are `type=password`, and one click on "Save locally" is all it takes.
  - **The plugin writes the file, not you**: by default `$DSH_HOME/_secrets/<file>.json` (`~/.dsh/_secrets` when `DSH_HOME` is unset; override with `config.secretsDir` / `DSH_SECRETS_DIR`, and a relative path is refused rather than resolved against an unpredictable cwd). Written atomically (tmp + rename), `0600` where POSIX modes exist, with `_meta` recording the source and save time. The file name comes from the registry and must be a bare name — `../x`, subdirectories or a non-`.json` name are errors.
  - **Only a masked preview ever comes back**: the panel and every endpoint return `saved` plus `cli_****（12 位）`-style previews. The plaintext never appears in an API response, a log line, or a tool result. That is also why there is deliberately **no tool that saves a credential** — a secret passed as a tool argument would land in the conversation transcript; saving happens in the panel's paste box only.
  - **The inputs are uncontrolled**: the value lives in the DOM until you press save and never enters component state, so it cannot be swept up by a log or a debug dump. A blank box means "keep what is already saved", so "paste the App Secret today, the App ID tomorrow" works.
  - **What is refused**: undeclared fields (`unknown credential field`), values over 4096 characters, invisible control characters, and an all-empty save. A refused save changes nothing on disk.
- **★ A wrong record can be taken back** (Phase 2): the preview pane has "Delete this record"; for the agent it is `inbox_remove` / `POST /api/remove`. Removing one rewrites `manifest.jsonl` and deletes only the files that record **owns**; if two old records still share one file, the file is kept so the survivor's body is not emptied.
- **★ Third-party capabilities moved in-tree** (Phase 3): the guidance used to say "hand the link to envoy-dsh / dsh-link-parse", "use dsh-scrape-webpage / dsh-read-url for the body", "sync with dsh-cubox", "dsh-email fetches the mail", "export with weread-export". **None of those packages is installed here**, and naming them is worse than useless: a name printed in guidance is a name someone else can register first, and then their code runs with your browser data. So the capabilities now live in this plugin, with **zero third-party dependencies**:
  - **Link → Markdown** (`lib/fetchdoc.js`): the 语雀 / web clipping / Zhihu / link-parse rows get a real input box plus "▶ Fetch and archive". It converts HTML to Markdown itself (headings, lists, quotes, tables, images, links, fenced code) and prefers the `<article>` / `<main>` / content container over page chrome. **Safety**: https only, no credentials inside the URL, localhost / private ranges / the 169.254 metadata address refused, and **the final URL after a redirect is re-checked** (otherwise a public link could 302 into your LAN), 5 MB cap, 20 s timeout.
  - **WeRead highlight export** (`lib/weread.js`): calls the official read-only endpoints with the Cookie you pasted (shelf → per-book bookmarks), renders Markdown with front-matter grouped by chapter. The row button is "▶ 导出划线".
  - **Cubox collection sync** (`lib/cubox.js`): pulls your cards through the pasted API link (the host must be `cubox.pro` or a subdomain), one record per card. The row button is "▶ 同步收藏".
  - **Mail over IMAP** (`lib/mailimap.js`): a hand-written client on `node:tls` only. Its commands are `SELECT` / `FETCH` / `LOGOUT`, it uses `BODY.PEEK` (**your mail is never marked read**), decodes multipart / base64 / quoted-printable / RFC 2047 subjects, reduces HTML to text, and skips attachments. The row button is "▶ 收取新邮件".
  - Each of those buttons needs its credential pasted on the same row first; when it is missing the row says "还没有保存 …（先在上面那个输入框里粘贴并保存）" instead of sending an empty request.

**Official MCP / API sources** (Tencent Docs / Feishu / Quark / Notion …) need a one-time account authorization and are **NOT connected yet** — the registry honestly marks them `needs-auth` rather than pretending they run. Config lives in `<dataDir>/adapters.json`, never in the profile's user patch layer.

## Compliance red line

Personal WeChat / QQ chat history is only handled through **official** backup / "合并转发" / share exports that the user produces, then imported as files. The plugin never reads or decrypts a local chat database. (The `chatlog` project was taken down 2025-10-20 after an official letter; Tencent filed a GitHub complaint 2026-01-22 against projects that reverse local database keys.)

## How to use

1. Open **Source inbox** from the sidebar.
2. Produce an official export on the source platform (see the per-source guide in the 数据源清单 card). If you first need to log in or mint a token, click that row's **↗ button** — the system browser opens the platform's official page — then follow the numbered steps (each says what you obtain and where to put it). **Once you hold an App ID / Secret / token / app password, paste it into that row's input box and click "Save locally"** — no file to create, no JSON to hand-write; the plugin stores it and the row shows only a masked preview such as `cli_****（12 位）`.
3. **Read instead of export where you can**: sources with "⟳ Read it for me" (Quark / Cubox / Xiaoyuzhou / Figma / Douyin / Xiaohongshu / 视频号 / 即梦 / Zhihu / 公众号) need one click — the first click opens the plugin's own browser window for a QR scan, the second turns the list into archived records.
4. **Use the "▶" buttons where they appear**: link → Markdown (语雀 / web clipping / Zhihu / link-parse — paste an https link into the box, then "▶ Fetch and archive"), highlight export (WeRead), collection sync (Cubox), fetch mail (email). Those capabilities ship inside the plugin; there is nothing to install. Paste the row's credential once before the first use.
5. For everything else, paste its **absolute path** into the import wizard and click Import. Records appear in the list; click one to preview its normalized text.
6. Ask the model to use the `inbox_*` tools, or just browse the workbench.

## Data location

By default `<DSH_HOME>/data/dsh-source-inbox/` (e.g. `D:\Program Files (x86)\DSH_Data\data\dsh-source-inbox`). Override with `config.dataDir` or the `DSH_SOURCE_INBOX_DIR` environment variable. The append-only index is `manifest.jsonl`; subfolders are `_raw/`, `materialized/`, `reference/`, `assets/`, `dropzone/` (default watch dir), `browser-profile/` (the controlled browser's own profile — login state never leaves it), plus `adapters.json` (watcher config). A watch dir must not sit inside the archive root (feedback-loop guard).

Large media files are **not** copied into the store. Keep the original export where it is; the record only holds a pointer and a text shadow stub to be filled by a later transcript/OCR/summary adapter.
